# Security Policy
 
## 🔒 Reporting a Vulnerability

We take security seriously. If you discover a security vulnerability in this project, please report it responsibly.

### How to Report

1. **Do not** open a public GitHub issue for security vulnerabilities.
2. Email the maintainer directly or use GitHub's **Security Advisories** feature (if enabled).
3. Provide a clear description of the issue, including:
   - Steps to reproduce
   - Affected project(s)
   - Potential impact
   - Suggested fix (if any)

### What to Expect

- **Acknowledgment** within 48 hours
- **Status update** within 7 days
- **Credit** in the release notes (unless you prefer to remain anonymous)
- **Resolve** the issue in a timely manner

### Scope

This policy applies to:
- `main` branch
- All public project folders
- `scripts/` directory

### Out of Scope

- Third-party dependencies (report to the upstream maintainer)
- Denial of Service attacks on publicly hosted instances
- Social engineering

---

## 🛡️ Security Best Practices for Contributors

- Never commit secrets, API keys, or `.env` files
- Use strong, unique passwords and 2FA
- Keep dependencies updated
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md)
- Report any suspicious behavior immediately

---

## 📋 Security Checklist

- [ ] No secrets exposed in code or documentation
- [ ] User input is validated and sanitized
- [ ] No hardcoded credentials
- [ ] Dependencies are up to date
- [ ] No unnecessary file uploads
- [ ] Error messages do not leak sensitive information
